TritonAI Developer APIs

TritonAI provides a common gateway and emerging development patterns for campus teams exploring governed AI services. Access, data use, model routes, costs, and production readiness are reviewed for each project.

Browse current models and rates

The Model Hub is the authoritative place to review models currently offered through the gateway, their published capabilities, context windows, and rates.

Open the Model Hub

A shared development path

Builders can begin with a narrow use case and use the shared gateway, reusable skills, and pilot tooling where those capabilities are approved for the project. A prototype does not imply production approval.

  1. Define the need: identify the user, task, data, accountable owner, human review point, and success measure.
  2. Request access: submit enough context for the service team to review the appropriate model route and controls.
  3. Build a bounded prototype: use approved data and test quality, accessibility, security, cost, and failure handling.
  4. Plan for operation: confirm ownership, support, monitoring, and the production path before serving additional users.

TritonAI Harness pilot

The TritonAI Harness is being piloted as a workspace for bounded, tool-using AI workflows. It can coordinate model requests, approved tools, reusable skills, and multi-step work. Availability and supported capabilities are confirmed during project review.

Shared responsibility

Platform responsibilities

  • Common gateway operations
  • Reusable patterns and published standards
  • Review of the proposed service path
  • Current access and model information

Project responsibilities

  • Application logic and approved data
  • Accessibility and testing
  • End-user support
  • Named business and technical owners

Request access

Submit the access request with your use case and project context. The service team will confirm eligibility, available model routes, data-handling requirements, current rates, and any additional review needed.
